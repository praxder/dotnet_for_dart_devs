## Types reveal where work happens

`IEnumerable<T>` represents synchronous iteration. LINQ operators over it usually run in process and many are deferred until enumeration. `IAsyncEnumerable<T>` represents asynchronous streaming. `IQueryable<T>` is an expression tree that a provider may translate for remote execution.

Dapper’s normal `QueryAsync<T>` awaits the database read and returns buffered results by default. The returned `IEnumerable<T>` does not mean the SQL will rerun lazily. By contrast, a LINQ-to-database `IQueryable<T>` may execute when materialized.

```csharp
var adults = people.Where(person => person.Age >= 18); // recipe
people.Add(new Person("Kai", 30));
var snapshot = adults.ToList();                        // executes now
```

## Boundaries change the cost model

Crossing process, network, database, or serialization boundaries changes failure modes and performance. A method that appears to return a collection may hold a connection open while the caller enumerates. A JSON response may buffer the entire result unless explicit streaming is used.

Materialize before disposing a required resource. Stream when data is large and the protocol supports partial delivery, but then design for cancellation and mid-stream failure. Avoid multiple enumeration when the source performs work or cannot be replayed.

## Questions to ask

- What triggers execution?
- Where does each filter run?
- How long must the underlying resource remain alive?
- Can the sequence be enumerated twice?
- Is cancellation observed between items?
- Does the consumer need a snapshot or a stream?
